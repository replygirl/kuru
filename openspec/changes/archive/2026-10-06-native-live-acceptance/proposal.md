# Proposal

## Why

Offline fixtures establish serialization and private reasoning contracts, but cannot establish native provider usage or live facing progress. A deliberately ignored acceptance fixture can observe those existing contracts without opening real project memory.

## What Changes

- Add one opt-in owning-app fixture using the native codex factory, existing Harness and terminal UI with synthetic project input and isolated temporary Dolt memory.
- Limit execution to gpt-5.6-luna, six completions, finite input and streamed output, and a deadline; retain advertised capability metadata and distinguish absent, zero and positive cached usage.
- Exercise existing pre-turn rewrite and post-turn annotation hooks, private summary persistence and fresh-context exclusion, and normal public replay without adding production behavior.

## Impact

- Only app test sources and this test change record are affected; ordinary CI remains offline because the fixture is ignored.
- Native authentication uses the factory's existing separate data-directory argument. No credential inspection, imports, real legacy migration, dependency changes or product configuration changes are involved.
- Wrapper request observations supplement existing serializer tests and do not prove final wire bytes. Missing live reasoning, tool or cache observations remain explicitly unobserved.
