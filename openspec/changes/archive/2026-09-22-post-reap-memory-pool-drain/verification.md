Replacement normal-hook diagnosis, 2026-09-22: combined coverage reached the `kuru` library suite, where the two `memory_notice` presentation tests both failed while opening a temporary store. The primary error was `memory supervisor readiness deadline exceeded`; the later `memory supervisor shutdown deadline exceeded; lifecycle lock remains authoritative` was the secondary `startup_failure` cleanup result while the supervisor was still live. No store or pool-close path had been reached, so this does not reproduce the post-reap drain defect. The parent timed out the complete readiness-frame exchange after launching the supervisor; retained output does not establish whether that supervisor had spawned Dolt, because its private `server.log` is published only after engine cleanup. Unix parent cancellation closes the supervisor lifetime pipe; startup selects that EOF alongside authenticated Dolt readiness after the synchronous child spawn, then performs bounded exact-child shutdown. If that cleanup misses the parent bound, the returned error stays fail-closed and `Owner::drop` independently retains the lifecycle guard and supervisor handle through actual reap. The existing real-Dolt `parent_close_during_selected_port_takeover_never_retries` fixture directly proves the ordinary post-spawn EOF path reaps the child and does not retry.

The hook ran both presentation tests concurrently under `RUST_TEST_THREADS=2`; the two tests were simultaneously reported live beyond 60 seconds. Distinct isolated stores remain valid at that configured concurrency. The exact retained instrumented binary later reran both tests together with coverage's unset prepared-supervisor override and passed 2/2 in 6.39 seconds. That establishes nondeterminism, but does not identify why the timed-out supervisor stalled. The concrete fixture defect is narrower: the two-mode test could begin its next temporary store after only dropping the previous owner into asynchronous cleanup, and both tests could finish without awaiting their final owner cleanup. Each store now closes explicitly before the next iteration or test completion, and the fixtures require the retained temporary directory to be removed after close. The owning memory package retains concurrent-owner and startup-cancellation acceptance coverage. Corrected source passed the package-owned filtered task with its normal `RUST_TEST_THREADS=2`: `mise run //apps/kuru-tui:test -- memory_notice::tests::` ran the two tests 2/2 in 5.25 seconds and completed all filtered targets in 63.07 seconds.
