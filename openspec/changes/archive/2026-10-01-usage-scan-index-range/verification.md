- [x] 1.1 @integration (agent) plan test `bound_range_queries_plan_as_primary_key_ranges` against a live isolated store: each rewritten query string (owned first page, owned later page, session index first and later page, the `mark_new_session` probe) is taken from the same `KeyRange::page` / `KeyRange::any_for_update` the production code binds, its arguments are bound through sqlx with production's Rust types, and `EXPLAIN PLAN` is read for it -> each plan is `Limit` over `IndexedTableAccess(state)` with `index: [state.key]` and `filters: [{[[start], [end])}]` (first page, probe) or `[{([after], [end])}]` (later page) holding exactly the bound bytes, with neither `TopN` nor a bare `Table` node; the old query bound the same way plans as `TopN(Limit: [128]; BINARY(state.key) ASC)` over `Filter` over `Table`, and the old probe as `GroupBy` over `Filter` over `Table` (negative control).
