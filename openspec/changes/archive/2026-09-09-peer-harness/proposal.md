## Why

Conventional chat harnesses organize cognition around one supervisor and its workers. Kuru makes persistent peer parts and their changing relationships the native architecture so users can explore computational interpretations of psychological frameworks while retaining familiar developer tools.

## What Changes

- Build a Rust monorepo with an interactive TUI and scriptable CLI.
- Add IFS, polyvagal, Freudian, and Jungian framework configurations, isolated part memories, peer messaging, temporary speaking relationships, and reversible dreaming changes.
- Integrate OpenAI through Codex app-server authentication and the Responses API, with dynamic model and effort selection; add deterministic offline demo operation.
- Provide constrained filesystem tools, explicitly enabled shell execution, MCP clients, and A2A communication.
- Establish cospec, mise, hk, repeatable checks with at least 90% meaningful line coverage, source installation, checksum-verified release installation/update, and CI/release workflows.

## Capabilities

### New Capabilities

- `peer-cognition`: persistent equal actors, framework modes, peer routing, relationships, dreaming, isolated memory.
- `chat-harness`: TUI and CLI, model selection, layered configuration, instruction loading and session persistence.
- `provider-tools`: authentication and inference providers, filesystem and shell tools, MCP and A2A protocols.
- `repository-delivery`: reproducible engineering checks, installation, update, release packaging and documentation.

### Modified Capabilities

None.

## Impact

New `apps/tui`, `packages/kuru-core`, `packages/kuru-connectors`, and `packages/kuru-runtime` Rust crates. SQLite stores local state separately from tool roots. New release workflows and local installer scripts make no assumption that a public release already exists. No existing application migrations or breaking changes.
