# Design

## Context

Run owns one controlled Harness turn, a broadcast event receiver, replaceable FacingProgress and existing awaited shutdown/memory/diagnostic cleanup. Its final print currently blocks before shutdown. Current exact request mismatch is a generic admission error; the adapter needs a narrow typed marker, not error-message interpretation. Accepted C1/N3/U2 are normally integrated; current main integration changes no accepted source bytes.

## Goals / Non-Goals

**Goals:** Meet the proposal and headless-run-stream requirements using one concrete CLI adapter around existing admission and cleanup.

**Non-Goals:** No batch loop, control protocol, new journal/outbox, provider behavior, generic writer scheduler or platform descriptor-mode mutation. No raw Event, private summary, cognitive argument/result, foreign history or tool result output. No new dependency or tool pin.

## Decisions

1. Validate Run input before `paths`, retained workspace, configuration/trust, diagnostics, provider, tools or memory. Read redirected stdin once with MAX+1 bounded UTF-8 input; aggregate prompt at most 131072 bytes. Preserve argv exactly when the pipe is empty; when both are nonempty compose `argv + "\n\nPiped input (literal data):\n" + stdin`. TTY stdin is never read and requires argv. Bare Kuru remains interactive. Pre-authority blocking stdin may run on a blocking reader; interrupted binary input exits 130 before authority activation so Tokio cannot wait forever for that reader. This explicit effect-free exception must not extend into admitted work. Ignoring pipe data or reading it after opening memory is rejected.
2. Use one ordinary OS stdout-only writer, one bounded in-flight record and an acknowledgement. It owns no Harness, memory, provider, ToolHost, claim or lifecycle resource and does not run in Tokio's blocking pool. Main polling continues the same pinned controlled future and signal listener while writes are pending. Successful output acknowledges and joins the finished writer; on blocked output cancellation, finish all authority cleanup before returning typed exit 130 without joining a kernel-blocked stdout-only thread. Process termination ends that thread. A closed pipe produces typed 141 after the same cleanup. No new timer, write deadline or global nonblocking flag is introduced. Synchronous writes in the select loop and awaiting an uninterruptible blocking-pool writer are rejected because either can prevent cleanup.
3. Keep finite JSONL v1 records: `started`, `status`, `snapshot`, `gap`, `terminal`; envelope `{version, seq, kind, turn, detail}` uses checked sequence and a domain-separated exact turn digest rather than raw caller ID. Status is a fixed phase or tool started/settled category from typed fields, without actor/private body, arguments, result, raw error or endpoint. Facing text is bounded, redacted and control-sanitized, keyed to exact turn and request round with its actual snapshot sequence/truncation. Summary/activity payloads are excluded. One pending public status plus one latest snapshot bounds buffering; omissions accumulate safely. Exact broadcast lag is distinct from observed coalescing and unknown watch replacement loss. No record implies lossless token delivery or invents admission identity/order for replay. Raw Event serialization is rejected.
4. Emit final terminal only after owned authority cleanup, at most once when output remains writable. Completed result retains projected final answer, session, token/limit/outcome metadata and `reused`; terminal answer is bounded with explicit truncation. The legacy final `--json` bytes retain the existing TurnOutput shape rather than wrapping/reprojecting it. It uses the same acknowledged stdout boundary; plain output remains answer text. Hook errors, compaction notices, debug ring location and ordinary error presentation remain stderr-only. Preserve ready-result-before-signal selection and never rewrite a completed journal because output was interrupted.
5. Classify exact typed outcomes, not string fragments. Exit 0 denotes completed durable output (including nonfatal denied/failed tools or existing empty/limited outcomes); 2 denotes bounded input/CLI or exact request-mismatch rejection; 3 denotes exact overall permission denial; 130 denotes controlled cancellation or interruption of blocked delivery; 141 denotes broken stdout; 1 denotes other failure, uncertainty or cleanup failure. Stream terminal separates completed/rejected/denied/cancelled/failed status from proved completion, no-effect rejection or unresolved settlement. A generic error cannot prove no effects; no automatic rerun follows partial or uncertain delivery. A completed output interrupted by SIGINT remains retryable only by the existing exact completed-turn path.

6. One private boxed/pinned Ctrl-C future is first-polled before input and retained through setup, drive, controlled shutdown and final write ACKs. Reuse it until consumed, then disable it without repolling completion; observe queued setup interruption before turn admission. This avoids dropping a captured signal on activity/ACK selection or phase transitions. Retain the original Run token through `shutdown_controlled(dream, &token)`. Poll SIGINT while awaiting that same shutdown; cancel and await it before exit 130. Already-cancelled tokens prevent starting an exit dream. The ordinary shutdown wrapper, dream policy, 30-second budget and all cleanup remain unchanged. A sole typed cancellation remains identifiable; cleanup failures remain failures. The signal branch always means exit 130 even if the operation later returns generic success; a completed journal is never rewritten.

## Risks / Trade-offs

- [Held output cannot deliver a terminal record] → Document partial output and exact retry; signal cancellation still settles owned work and exits. The stdout-only thread holds bounded bytes and no authority.
- [Progress is replaceable and request rounds differ] → Match exact turn/round, retain snapshot sequence/truncation and distinguish unknown snapshot loss from exact broadcast omission counts.
- [Output failure can follow an accepted effect] → Await the same controlled future and existing exact recovery; never infer no effect from a pipe error or replay an ambiguous call.
- [N4 concurrently changes CLI lifecycle] → Separate worktrees and narrow owned sections; integrate stable commits and review the actual cleanup/lease order without adding another framework.

## Operational surface

Explicit one-shot `kuru run` retains current routes, trust, budgets, project owner, binary, native platforms and diagnostics. No endpoint, secret, deployment role, supervisor or runtime dependency is added. Functional acceptance uses isolated HTTP/process fixtures; native/full coverage and paid live calls remain distinct unrun evidence until delivery.

## Integration contract

The CLI owns the opt-in JSONL v1 encoder and stdin/output lifecycle; runtime owns exact request admission and controlled settlement. The existing provider fixture uses its real HTTP transport, not a new SDK/route. No current Event/TurnOutput/private RPC/journal schema changes. Every JSONL envelope has numeric `version: 1`, checked increasing `seq`, one of the five fixed `kind` values, a 64-hex domain-separated exact `turn` digest and allowlisted `detail` object. IDs never become authority or replay commands. Started has bounded session identity; status has fixed phase/tool status plus projected bounded actual call/name metadata when applicable; snapshot has request round, source sequence, facing text and truncation; gap distinguishes exact broadcast omissions, observed local coalescing and unknown watch loss; terminal has status/settlement and successful public result metadata when available. Unknown public record kinds/versions must be handled by downstream consumers as unsupported, not decoded as raw runtime events. These stream caps do not truncate legacy final JSON: it serializes the existing accepted TurnOutput under existing provider-response and turn/persistence budgets, without adding a total serialization cap. Record encoding is capped at 256 KiB and text at 32 KiB before escaped JSON expansion; queue state retains at most one pending status and one latest snapshot plus scalar gap counters and one in-flight record.

| Exit | Exact condition | Settlement claim |
| --- | --- | --- |
| 0 | Controlled turn completed and final delivery acknowledged | Completed; empty/limited/nonfatal tool failures retain their existing metadata |
| 2 | Input/CLI rejection or typed exact request mismatch | No new admitted work for this rejected request; prior same-ID result is unchanged |
| 3 | Exact overall typed permission denial | Denied; no blanket assertion about earlier unrelated effects |
| 130 | Controlled cancellation or interruption of held output | Cancelled or already completed, as actually proved; completed journal is unchanged |
| 141 | Broken stdout | Output incomplete; accepted work is not undone or replayed |
| 1 | Other failure/uncertainty or cleanup failure | Unresolved unless an actual completion is independently retained |

Printed errors/hook/compaction/debug metadata are stderr-only and cannot invalidate an already accepted completed journal. The final `--json` contract remains its existing full final object, not this stream envelope. The terminal is emitted at most once after actual cleanup; a pipe that is closed or held during interruption can prevent delivery and cannot establish a lossless stream.
