## 6. Second review round

- [x] 6.1 Read `versions/.leftovers/<name>.json` through a bounded, checked path instead of a raw `fs::read`. Added `read_leftover_receipt` (`provision.rs`), which reads through the already-open `.leftovers` `Directory` with a `LEFTOVER_RECEIPT_LIMIT = 16 KiB` cap and an identity `verify` afterward, mirroring `files::read_bytes`'s contract; `sweep_one_leftover_stage` now calls it in place of the unbounded read. An over-limit or unparsable receipt is left in place and counted as `remaining`, never panicked on or silently dropped.
- [x] 6.2 Route the warm-open sweep's blocking filesystem work through `tokio::task::spawn_blocking`. `warm_sweep_if_receipted` is now `async`; the single lock-free `symlink_metadata` check on `.leftovers` stays on the calling task exactly as before, but the receipt-presence scan, the non-blocking `try_cache_lock`, and `sweep_leftover_stages` (including its `remove_tree` calls) now run inside one `spawn_blocking` closure, matching the cold path's own extraction/probe pattern (`provision.rs:148`, `provision.rs:160`). The one call site (`provision.rs:129`) now moves its owned `cache`/`versions` into the call and awaits it.
- [x] 6.3 Only count a leftover stage as `collected` when its receipt is actually removed. `collect_leftover_receipt` previously incremented `collected` unconditionally, even when the receipt read or `remove_file` failed. It now increments `collected` only when both the read and the removal succeed, and `remaining` otherwise — reporting, never miscounting, a stage whose tree is gone but whose receipt removal could not be confirmed.
- [x] 6.4 Add `first_cause` to the retained-stage diagnostics record. The roadmap ruling requires the report to carry "first cause with OS error"; the ring event carried the numeric `os_error` but not the cause string itself, while `design.md`'s Surfacing decision already promised "cause" would reach the ring. `emit_retained_stage_diagnostic` now also emits `first_cause` (the same `{:#}`-rendered chain the receipt stores); `SafeFields::allowed` (`apps/kuru-tui/src/diagnostics.rs`) admits it with the same 256-character truncation every other string field gets, and `layer_admits_the_retained_install_stage_target_and_its_fixed_fields` asserts it round-trips.
