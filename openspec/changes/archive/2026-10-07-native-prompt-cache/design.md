# Design

## Context

Byte-identical common text inside changing top-level instructions is not proof of native reuse. The native endpoint rejected the API's explicit cache breakpoint and diagnostic cache options with HTTP 400. Identical native controls can alternate hits and misses; selected model, actual tool inventory and server rendering affect eligibility. Plain native developer content blocks have reported positive cached input in ordinary tool-bearing harness completions; complete acceptance must still verify distinct actors and normal completion.

## Decisions

The runtime records the byte boundary when constructing common instructions rather than having the connector parse actor prompt prose. Completion requests retain the full instruction text and optional boundary. The subscription connector validates it and places the exact shared/local segments, in order, into plain developer content blocks. The nonempty top-level instructions direct the model to those developer instructions. A SHA-256 routing key groups common instructions, sorted actually offered tools, model and effort; actor identity, transcript, notes and private input do not participate. Phase inventories remain separate without granting extra capabilities. API-key/custom routes and callers without metadata keep their original request shape. Native continuations retain their original protocol input; only final-wire sizing ranges shift past the injected developer item.

## Integration contract

The connector owns native `input_text` and `prompt_cache_key` serialization and sends neither rejected API cache controls nor speculative affinity state. Direct API-key and native subscription credentials remain separate. Context estimates measure the actual final body and attribute both top-level and injected developer instructions; opaque output ranges remain correct. No authentication route, dependency, production prompt padding or cache prewarm is added.

## Risks / Trade-offs

Caching is opportunistic, not guaranteed by layout or routing key. The paid fixture uses advertised GPT-5.5 at low effort; preceding GPT-5.6-Luna tool-bearing runs reported zero. Successful acceptance must report actual positive usage on a later actor with a matching common prefix and offered inventory, under the existing six-stream/64k-input/16KiB-output/deadline bounds. The fixture distinguishes all-phase provider summaries from observed facing summaries and verifies each facing session/actor/turn's private record. Existing exact resume and leak checks remain. Local HTTP regression proves the wire contract; no fake peer response establishes a live hit. Accounting preserves absent, zero and positive reports and unapplied cache-write pricing.
