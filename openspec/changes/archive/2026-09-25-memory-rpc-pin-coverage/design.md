## Context

`memory-rpc-operation-contract` added an exhaustive operation contract and a
fixture that pins the memory service wire surface at protocol 1.7. Review found
nested wire types with a single sampled shape, a `null` price schedule, a
wildcard in `unit_receipt_view`, a hard-coded deadline in the test-support
paused exchange, and a bless check that accepted any different version rather
than a greater one.

## Goals / Non-Goals

**Goals:** pin one shape per variant for every nested wire enum reachable from
requests. Require a strictly greater version to regenerate. Remove the last
classification-path wildcard.

**Non-Goals:** response payload shapes beyond tag lists, handshake pinning,
`ServiceFault` consolidation (R5), and any wire or version change.

## Decisions

1. **Generic per-variant sampling.** Every sample set is reduced to
   `(tag, shape)` pairs and compared with the serde variant list. Internally
   tagged samples drop their tag key. Externally tagged samples use their single
   key. Rejected: listing only tags for nested enums, which misses field
   renames.
2. **Phase through its public carrier.** `Phase` is private to
   `store/export.rs`, so its samples and unknown-variant probe go through
   `ExportCursor` JSON. Rejected: widening its visibility for a test.
3. **Usage proofs from ledger samples.** Each mutating ledger sample's `proof()`
   produces the real proof, so the shapes cannot drift from the constructors.
4. **Strictly greater version, runtime fixture read.** The test reads the
   fixture from the package directory. Regeneration writes only if the fixture
   is absent (initial record) or `(major, minor)` is strictly greater than the
   recorded version. The fixture for this unmerged branch is regenerated by
   removing it and blessing, not by hand editing. Rejected: an override flag
   for unchanged versions, which would be a standing loophole.
5. **Explicit arms in `unit_receipt_view`.** Every `ServiceCall` variant is
   named, so a new call must choose its receipt view.

## Risks / Trade-offs

- [A hand edit, or deleting and regenerating the fixture, can still record a
  changed surface at an unchanged version] → Both appear as a fixture diff
  without a `service.rs` bump. Review is the gate. The docs name this risk.
- [Two branches bump to the same minor concurrently] → The second merge
  conflicts on the fixture and on `PROTOCOL_MINOR`. It must rebase, take the
  next minor and regenerate.
- [Runtime fixture read needs the source tree] → Package tests always run from
  the checkout, and CI tests do too.

## Seam ownership

`service/rpc/contract_tests.rs` owns the samples and pin. `service.rs` owns the
version constants. No runtime state moves.

## Integration contract

The memory service wire protocol stays at 1.7. This change pins more of its
existing surface.
