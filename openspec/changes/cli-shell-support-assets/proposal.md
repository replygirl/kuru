## Why

Kuru's release archives currently carry the executable, license and README, but no installable shell completions or man page. Hand-maintained copies would drift from the actual CLI, and adding entries to the existing executable archive would break the exact-member checks in already-published installers and updaters.

## What Changes

- Generate Bash, Zsh, Fish and PowerShell completions and one man page from the authoritative Clap CLI definition through a pure path that runs before workspace configuration, trust, memory, provider or tool activation.
- Pair each native executable archive with one target-specific checksum-verified shell-support envelope containing the same fixed five-file inventory: tar.gz for Unix targets and ZIP for Windows. Verify its generated bytes against that target's executable; target outputs may differ. Keep existing platform executable archives and their three-member layouts unchanged so older installers and updaters still accept the executable.
- Make current installer/update paths and release verification validate and install the corresponding support envelope when using the new release contract, under a versioned directory inside the selected installation root. Preserve the existing executable receipt and report partial outcomes truthfully. Existing older clients can still update the executable; they cannot retroactively install a new support asset, so the current installer or new binary must provide a documented explicit repair path.
- Document stock-shell and man activation through the fixed installed executable's pure generator, along with pinned versioned file locations. A new shell session or explicit reload picks up the current settled executable without pinning a profile to obsolete static bytes. Homebrew tap/formula publication, package-manager ownership handling, Unix rollback and update notices remain separate P24b/P25 work.

## Capabilities

### New Capabilities

- `shell-support`: CLI-derived generation, exact support-archive inventory, and installable shell/man assets.

### Modified Capabilities

- `repository-delivery`: Verified installation and update of a separate shell-support archive while retaining the legacy executable archive contract.
- `release-automation`: Exact release asset/checksum inventory and candidate/published verification for the added archive.
- `public-documentation`: Shell completion activation, man-page availability and old-client upgrade limits.

## Impact

`apps/kuru-tui` owns the Clap-backed generator and its package-scoped mise task. `packages/kuru-delivery` consumes pre-generated bounded inputs and updates archive, installer, updater, candidate and published verification contracts; the Unix and Windows bootstraps each install only verified support bytes within their existing explicit installation roots. Release workflow inventory and installation docs change together. New pinned Rust generator dependencies, if needed, update workspace manifests and Cargo.lock together. No memory schema or runtime protocol migration, new language project, provider request, Homebrew tap mutation or external publication belongs to this change.

## Surfaces
